## 4. التعديل الإضافي المطلوب — operation_id لأمر الشراء

### 4.1 الوضع الحالي المثبت

- الدالة المساعدة موجودة مرة واحدة في Buyer:

```javascript
function buyerOperationId(){
    return 'buyer-'+Date.now()+'-'+Math.random().toString(36).slice(2);
}
```

- دالة `App.api(operation,payload)` تنسخ `payload.operation_id` إلى الطلب المرسل إلى `save-purchase-order` إذا كانت الخاصية موجودة.
- في المصدر الحالي للفرع وقت الفحص، استدعاء `CREATE_PO` لا يرسل `operation_id`.
- توجد مواضع أخرى في Buyer تستخدم `buyerOperationId()` مع عمليات أخرى؛ لا تضف تعريفًا ثانيًا للدالة.

### 4.2 موضع التعديل الأول

داخل:

```javascript
createPO:async function(){
```

ابحث عن سطر تهيئة المتغيرات:

```javascript
var suppliers=d[0].filter(function(x){return x.is_active!==false;}),items=d[1],branches=d[2],settings=d[3][0]||{},lines=[],self=this;
```

أضف بعده مباشرة:

```javascript
var operationId=buyerOperationId();
```

فيصبح المقطع:

```javascript
var suppliers=d[0].filter(function(x){return x.is_active!==false;}),items=d[1],branches=d[2],settings=d[3][0]||{},lines=[],self=this;
var operationId=buyerOperationId();
```

### 4.3 موضع التعديل الثاني

داخل `preConfirm` في دالة `createPO`، ابحث عن:

```javascript
self.api('CREATE_PO',{supplier_id:supplier,
```

أضف الخاصية التالية في بداية كائن الطلب:

```javascript
self.api('CREATE_PO',{operation_id:operationId,supplier_id:supplier,
```

اترك جميع الخصائص الأخرى كما هي؛ لا تعِد كتابة الدالة أو النموذج.

### 4.4 سبب موضع التوليد

يجب توليد `operationId` مرة واحدة عند إنشاء نموذج PO، وخارج `preConfirm`. إعادة استخدام المعرف نفسه عند إعادة محاولة الإرسال من النموذج ذاته هي السلوك المطلوب. لا تولّد المعرف داخل `preConfirm` لأن ذلك سينشئ قيمة جديدة لكل محاولة.

### 4.5 شرط اعتماد هذا الإصلاح

تمرير المعرف من Buyer وحده لا يثبت منع التكرار. يجب التأكد من أن مسار `CREATE_PO` في Edge Function/RPC:
1. يستقبل `operation_id` من الطلب.
2. يمرره إلى طبقة العملية الذرية دون إسقاطه.
3. يفرض قيد/سجل Idempotency فعليًا على نطاق المستخدم/العملية وفق العقد المعتمد.
4. يعيد نتيجة العملية الأصلية عند تكرار الطلب بنفس المعرف.
5. لا ينشئ PO جديدًا عند إعادة المحاولة بنفس المعرف.

لا تغيّر Edge Function أو SQL/RPC ضمن هذا التعديل المحدود قبل فحص التوقيعات والعقد الحاليين وتحديد الحاجة بصورة مستقلة.
